> 适用版本：CetCryptoToolkit v2.3.x
> 作者：CetXiyuan（璟·汐源忆醉）

## 一、PKI 证书体系说明

PKI（公钥基础设施）是一套用于管理数字证书的体系。CetCryptoToolkit 支持**三级证书体系**：

```
一级根证书（RootCA）
  └── 二级根证书（SubCA）
        └── 终端证书（EndEntity）
```

**通俗理解**：
- **一级根证书**：最高权威，相当于"公安部"，自己给自己盖章，是整个信任链的起点
- **二级根证书**：中间机构，相当于"省公安厅"，由一级根证书授权
- **终端证书**：最终使用的证书，相当于"个人身份证"，由二级根证书签发，用于实际的加密通信或身份认证

---

## 二、快速生成一套完整证书

以下步骤演示如何从零生成一套完整的三级 PKI 证书。

### 第一步：生成一级根证书（RootCA）

1. 在主界面顶部的「证书类型」下拉框中，选择 **一级根证书(CetXiyuan)** 或 **一级根证书(Custom)**
   - `CetXiyuan`：使用作者预置的固定参数，适合快速测试
   - `Custom`：可自定义所有参数，适合正式使用
2. 点击「配置」按钮，打开证书配置对话框
3. 在配置对话框中设置：
   - **密钥类型**：RSA-2048（推荐）或 SM2（国密）
   - **有效期**：建议 3650 天（10年）
   - **CommonName**：证书名称，如 `My Root CA`
4. 点击「确定」关闭配置对话框
5. 在主界面点击「生成证书」按钮
6. 等待生成完成，查看输出目录中的文件

### 第二步：生成二级根证书（SubCA）

1. 「证书类型」选择 **二级根证书**
2. 点击「配置」，设置参数（有效期建议 1825 天，即 5 年）
3. 确认「签发者」显示为刚才生成的一级根证书
4. 点击「生成证书」

### 第三步：生成终端证书（EndEntity）

1. 「证书类型」选择 **终端证书**
2. 点击「配置」，重点设置：
   - **CommonName**：域名或服务名，如 `example.com`
   - **SAN（主题备用名称）**：填写实际使用的域名和 IP，如 `DNS:example.com,IP:192.168.1.1`
   - **有效期**：建议 365 天（1年）
3. 确认「签发者」显示为二级根证书
4. 点击「生成证书」

## 三、证书类型详解

### 3.1 一级根证书（RootCA）

| 参数 | 值 |
|------|---|
| 证书类型 | CA 证书 |
| pathlen | 1（最多允许 1 级中间 CA） |
| 密钥用途 | keyCertSign（签发证书）、cRLSign（签发吊销列表） |
| 签发者 | 自签（Issuer = Subject） |
| 有效期建议 | 10 年 |

**两种预设**：
- **CetXiyuan**：CN 固定为 `CetXiyuan Root CA Signing Authority`，参数不可修改，适合快速测试
- **Custom**：所有参数可自定义，适合正式部署

### 3.2 二级根证书（SubCA）

| 参数 | 值 |
|------|---|
| 证书类型 | CA 证书 |
| pathlen | 0（不允许再下级 CA） |
| 密钥用途 | keyCertSign、cRLSign |
| 签发者 | 一级根证书 |
| 有效期建议 | 5 年 |

### 3.3 终端证书（EndEntity）

| 参数 | 值 |
|------|---|
| 证书类型 | 非 CA 证书 |
| 密钥用途 | digitalSignature（数字签名）、keyEncipherment（密钥加密） |
| 扩展密钥用途 | serverAuth（服务器认证）、clientAuth（客户端认证） |
| SAN | 用户指定的 DNS 域名和 IP 地址 |
| 签发者 | 二级根证书 |
| 有效期建议 | 1 年 |

## 四、配置对话框参数说明

点击主界面「配置」按钮后，弹出证书配置对话框，各参数说明如下：

| 参数 | 说明 | 示例 |
|------|------|------|
| 密钥类型 | 非对称算法选择 | RSA-2048、EC prime256v1、SM2 |
| 有效期（天） | 证书有效天数 | 365、1825、3650 |
| CommonName (CN) | 证书主体名称 | `example.com`、`My Root CA` |
| 证书扩展字段 | X.509 v3 扩展，可手动编辑 | 见下方说明 |

**证书扩展字段格式**（每行一条）：

```
basicConstraints=critical,CA:TRUE,pathlen:1
keyUsage=critical,keyCertSign,cRLSign
subjectKeyIdentifier=hash
authorityKeyIdentifier=keyid:always,issuer:always
subjectAltName=DNS:example.com,IP:127.0.0.1
extendedKeyUsage=serverAuth,clientAuth
```

## 五、输出文件说明

每次生成证书，自动在 `<应用目录>/dir-certs/` 目录下输出以下文件：

| 文件名 | 格式 | 用途 |
|--------|------|------|
| `<name>.key.pem` | PEM | 私钥，**妥善保管，不可泄露** |
| `<name>.pub.pem` | PEM | 公钥 |
| `<name>.csr.pem` | PEM | 证书签名请求（CSR） |
| `<name>.crt.pem` | PEM | 证书（文本格式，可用记事本打开） |
| `<name>.crt.der` | DER | 证书（二进制格式，部分系统需要） |
| `chain.pem` | PEM | 证书链（SubCA + RootCA 拼接） |
| `chain.p7b` | PKCS#7 | 证书链（Windows 可直接双击导入） |
| `<name>.pfx` | PKCS#12 | 证书 + 私钥 + 证书链打包文件 |

> **PFX 文件默认密码**：`pfxpassword`

---

## 六、PFX 和 P7B 的使用场景

### PFX（PKCS#12）
- 包含：证书 + 私钥 + 完整证书链
- 用途：导入到 Windows 证书存储、IIS、Nginx（需先转换）、Java KeyStore
- 导入方式：Windows 下双击 `.pfx` 文件，按向导操作，输入密码 `pfxpassword`

### P7B（PKCS#7）
- 包含：证书链（不含私钥）
- 用途：在服务器上部署证书链，让客户端验证证书信任链
- 导入方式：Windows 下双击 `.p7b` 文件，可导入到证书存储

## 七、常见问题

**Q：浏览器提示"证书不受信任"**

A：需要将一级根证书（`RootCA.crt.pem`）导入到操作系统或浏览器的"受信任的根证书颁发机构"存储中。Windows 下：双击 `.crt` 文件 → 安装证书 → 选择"本地计算机" → 将所有证书放入"受信任的根证书颁发机构"。

---

**Q：私钥文件丢失怎么办**

A：私钥无法恢复，必须重新生成密钥对和证书。建议将 `.key.pem` 文件备份到安全位置。

---

**Q：如何配置 SAN（主题备用名称）**

A：在配置对话框的「证书扩展字段」中，修改 `subjectAltName` 行：

```
# 单域名
subjectAltName=DNS:example.com

# 多域名 + IP
subjectAltName=DNS:example.com,DNS:www.example.com,IP:192.168.1.100

# 通配符域名
subjectAltName=DNS:*.example.com
```

---

**Q：生成的证书文件名包含下划线**

A：CommonName 中包含不可用于文件名的字符（如 `*`、`/`、`:`、`?` 等），程序会自动将其替换为下划线。

---

**Q：如何验证证书是否正确签发**

A：使用 OpenSSL 命令行验证：

```bash
# 验证终端证书是否由证书链正确签发
openssl verify -CAfile chain.pem <name>.crt.pem

# 查看证书详情
openssl x509 -in <name>.crt.pem -text -noout
```

---

**Q：PFX 导入时提示密码错误**

A：PFX 默认密码为 `pfxpassword`（全小写）。如果在配置对话框中设置了自定义密码，请使用对应密码。
