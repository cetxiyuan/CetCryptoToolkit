国密算法使用说明

适用版本：CetCryptoToolkit v2.3.x
作者：CetXiyuan（璟·汐源忆醉）

一、国密算法概述

国密算法是中国国家密码管理局（OSCCA）制定的密码标准，CetCryptoToolkit 通过 OpenSSL 3.x 提供完整支持：

算法 类型 对应国际算法 密钥长度 说明
SM2 非对称加密 / 签名 ECC（椭圆曲线） 256-bit 基于 SM2 椭圆曲线，用于加密和数字签名
SM3 摘要（哈希） SHA-256 — 输出 256-bit 摘要，用于数据完整性校验
SM4 对称加密 AES-128 128-bit 分组密码，支持 ECB/CBC/GCM/CTR 模式

OpenSSL 3.x 国密支持检测

程序启动时自动检测并打印：

SM2 is in default provider
SM3 is in default provider
SM4 is in default provider

若未打印，说明 OpenSSL 版本不支持国密，需升级至 3.0.18+。

二、与国际算法对照

场景 国际算法 国密算法 差异说明
非对称密钥生成 RSA-2048 / EC prime256v1 SM2 SM2 固定使用 256-bit 曲线，无需指定曲线名
数字签名 ECDSA + SHA256 SM2 + SM3 SM2 签名需额外传入 userId（ZA 值）
数据摘要 SHA-256 SM3 输出长度相同（256-bit），接口一致
对称加密 AES-128 SM4 密钥长度相同（128-bit），接口略有差异（见第五节）
证书签发 RSA/EC + SHA256 SM2 + SM3 hashAlgo 参数传 "sm3" 即可

三、SM2 使用

3.1 密钥对生成

OpenSSLHelper helper;

// 生成 SM2 密钥对，返回 QPair<公钥, 私钥>
QPair<QSslKey, QSslKey> keyPair = helper.genKeyPair("SM2");
QSslKey publicKey  = keyPair.first;
QSslKey privateKey = keyPair.second;

// 保存到文件
OpenSSLHelper::savePublicKey(publicKey, "sm2.pub.pem");
OpenSSLHelper::savePrivateKey(privateKey, "sm2.key.pem");

3.2 SM2 加解密

注意：SM2 标准主要用于签名，加密场景建议评估是否使用 SM4。

QByteArray plaintext = "Hello, SM2!";

// 公钥加密
QByteArray ciphertext = OpenSSLHelper::asymmetricEncrypt(plaintext, publicKey);

// 私钥解密
QByteArray decrypted = OpenSSLHelper::asymmetricDecrypt(ciphertext, privateKey);

3.3 SM2 数字签名

SM2 签名与 RSA/EC 的关键区别：必须传入 userId（用于计算 ZA 值）。

QByteArray data   = "待签名数据";
QByteArray userId = "1234567812345678";  // 标准默认值，16字节

// 对数据签名（内部先计算 SM3 摘要，再签名）
QByteArray signature = helper.signData(data, privateKey, "sm3", "", userId);

// 验签
bool ok = helper.signVerify(data, signature, publicKey, "sm3", userId);

⚠️ userId 说明：SM2 签名算法规定签名前需计算 ZA 值（包含用户标识和公钥信息），userId 默认为 "1234567812345678"（16字节 ASCII）。与第三方系统对接时，双方必须使用相同的 userId，否则验签必然失败。

3.4 SM2 签名格式转换

SM2 签名输出为 DER 格式（以 0x30 开头）。若收到裸格式（r||s 拼接）的签名，需先转换：

QByteArray rawSign = ...; // 64字节裸签名（r 32字节 + s 32字节）
if (rawSign.at(0) != 0x30) {
    rawSign = helper.sm2SignToDer(rawSign);  // 转为 DER 格式
}
bool ok = helper.signVerify(data, rawSign, publicKey, "sm3", userId);

3.5 SM2 公钥格式转换

// 裸公钥（04 + X + Y，65字节）转 DER 格式
QByteArray rawPubKey = ...; // 65字节非压缩公钥
QByteArray derPubKey = helper.sm2PubKeyToDer(rawPubKey);

四、SM3 使用

SM3 摘要接口与其他摘要算法完全一致：

QByteArray data = "待计算摘要的数据";

// 计算 SM3 摘要（输出 32字节 = 256-bit）
QByteArray hash = helper.digest(data, "SM3");

qDebug() << "SM3:" << hash.toHex().toUpper();
// 输出示例：SM3: "66C7F0F462EEEDD9D1F2D46BDC10E4E24167C4875CF2F7A2297DA02B8F4BA8E0"

五、SM4 使用

5.1 各模式说明

模式 IV 长度 密文格式 特点
ECB 不需要 密文 最简单，不推荐用于敏感数据
CBC 16字节 IV(16B) + 密文 常用，需要 padding
GCM 12字节 IV(12B) + 密文 + Tag(16B) 认证加密，推荐
CTR 16字节 IV(16B) + 密文 流加密模式，无 padding

5.2 SM4 加解密示例

QByteArray key  = QByteArray::fromHex("0123456789ABCDEF0123456789ABCDEF"); // 16字节
QByteArray iv   = QByteArray::fromHex("00000000000000000000000000000000"); // 16字节
QByteArray data = "Hello, SM4!";

// CBC 模式加密
QByteArray ciphertext = helper.sm4Encrypt(data, key, OpenSSLHelper::SYM_CBC, iv);
// 密文格式：IV(16字节) + 密文

// CBC 模式解密（需要传入 IV）
QByteArray plaintext = helper.sm4Decrypt(ciphertext, key, OpenSSLHelper::SYM_CBC, iv);

⚠️ SM4 与 AES 的接口差异：
- AES 解密时 IV 从密文前缀自动解析，不需要单独传入 IV
- SM4 解密时必须手动传入 IV（sm4Decrypt 第四个参数）

5.3 GCM 模式（推荐）

QByteArray key = QByteArray::fromHex("0123456789ABCDEF0123456789ABCDEF");
QByteArray iv  = QByteArray::fromHex("000000000000000000000000"); // GCM 用 12字节 IV
QByteArray data = "需要认证加密的数据";

// GCM 加密，输出：IV(12B) + 密文 + Tag(16B)
QByteArray ciphertext = helper.sm4Encrypt(data, key, OpenSSLHelper::SYM_GCM, iv);

// GCM 解密（传入完整密文，含 IV 前缀和 Tag 后缀）
QByteArray plaintext = helper.sm4Decrypt(ciphertext, key, OpenSSLHelper::SYM_GCM, iv);

六、SM2 证书签发

在 CertificateManager 中，选择密钥类型为 SM2，签名算法选 SM3，即可签发国密证书：

// 生成 SM2 密钥对
QPair<QSslKey, QSslKey> keyPair = helper.genKeyPair("SM2");

// 生成自签 SM2 根证书（hashAlgo 使用 "sm3"）
QStringList extensions = {
    "basicConstraints=critical,CA:TRUE,pathlen:1",
    "keyUsage=critical,keyCertSign,cRLSign"
};
QSslCertificate rootCert = helper.genSelfCert(
    3650,                          // 有效期 10 年
    "/C=CN/O=CetXiyuan/CN=SM2 Root CA",
    keyPair.second,                // SM2 私钥
    extensions,
    "sm3"                          // 使用 SM3 作为签名摘要算法
);

七、与第三方系统对接注意事项

  1. SM2 userId 必须协商一致：双方使用的 userId 必须完全相同，建议明确约定为 "1234567812345678"（GB/T 35276 标准默认值）。

  2. SM2 签名格式确认：部分系统使用裸格式（r||s，64字节），部分使用 DER 格式（ASN.1 编码）。接收到签名后检查首字节是否为 0x30，不是则调用 sm2SignToDer() 转换。

  3. SM4 IV 传递方式：本工具在密文中内嵌 IV 前缀，若对方系统 IV 单独传递，需在解密前手动拆分。

  4. SM3 摘要长度：SM3 输出 32字节（256-bit），与 SHA-256 相同，但算法不同，不可混用。

  5. 证书链验证：SM2 证书链验证需要对方系统支持 SM2 算法的 X.509 证书，部分老旧系统可能不支持。

  6. OpenSSL 版本要求：对方若使用 OpenSSL，需 1.1.1+ 版本才支持国密，推荐 3.0+。
